# The script language

Star Fox Command is not a hard-coded game: it is an engine driven by
**1,405 plain-text scripts**, left in the ROM because the original build
system (“mantabuilder”, September 26, 2006) copied them there as is. The game
reads and executes them with its own interpreter, which the port runs like the
rest of the game's code: modifying a script changes the game without touching
its code ([the procedure](assets.md)) — and the same grammar will be used to
write the continuation of the story.

The complete vocabulary — 205 commands, 54,427 calls, with signatures and real
examples — is listed in
[`script_reference.md`](../script_reference.md) (in French), generated by
`tools/analyze_scripts.py`.

## Syntax

Text files encoded in **Shift-JIS** (the developers' comments are in
Japanese), one command per line:

```
CreateEnemyTemplate eHoverEnemy <0 850 3500> <0 0 0> <1 1 1> 0
```

- `#` introduces a comment. Beware: the vast majority of commented-out lines
  are **disabled** commands, not prose. They are a mine of information about
  the engine, but must never be executed.
- `<x y z>` is a vector. Some commands, however, write their coordinates
  without angle brackets, such as `ActorObject`.
- Integers are written in decimal or hexadecimal (`0x0080` for the fog
  slopes).

## Path resolution

Scripts refer to files by their path in the ROM:
`/3D/Corneria/GrndSetA/CityA.mdl`. But that file does not exist as such: it
lives in the `Corneria.srl` archive. The game **mounts each `.srl` archive
under `/3D/<Planet>/`**: that path is written
`Corneria.srl:GrndSetA/CityA.mdl-cmp` for `tools/fichier_du_jeu.py`, and can
be found under `assets/cooked/_srl/Corneria/` once the archives are extracted.

## How a stage is described

A playable stage fits in a handful of commands:

```
Include  /3D/Corneria/Scripts/StageSetupA.txt
RegistModelSet GrndSetA  /3D/Corneria/GrndSetA/GrndSetA.tset
RegistHeightModel CityA  /3D/Corneria/GrndSetA/CityA.mdl
ClearHeightManager
SetHeightGridSize 2560
LoadHeightMap CityA Convex /3D/Corneria/GrndSetA/CityA_Col.hgt
RegistHeightGridObject HeightPoly CityA 3 5
```

The terrain is a **grid of 2,560-unit tiles**. `RegistHeightGridObject` — the
game's most-called command, 13,239 times — places the model registered under
the name `CityA` at cell (3, 5), with the collision tile loaded by
`LoadHeightMap`.

Two conventions coexist depending on the planet: Corneria declares its tiles
with `RegistHeightModel`, Aquas makes do with `RegistModel`.

### Scale and origin

Once their prologue has been executed (see [`format_mdl.md`](format_mdl.md)),
the models are **directly in world units**: a `CityBlank_Gr` tile measures
2,580 units, that is, a 2,560 cell plus the overlap at the seams.

The tiles, centered on their origin, are placed at
`((caseX − 4) × 2 560, 0, (caseZ − 4) × 2 560)`: the 9 × 9 grid is
**centered on the world origin**. Three clues agree — enemy positions spread
over ±5,200 units around zero, the player starts at `(0, 500, 6400)`, and the
bounds of the reconstructed terrain fall at ±11,520.

An earlier version of this document claimed a factor of 256 between “model
units” and world units. That was an artifact of a decoder bug, which did not
execute the prologue of half the models.

### Mission layers and enemies

A playable stage is the superposition of two scripts, registered separately
by `<Planet>Stage.txt`:

```
RegistStage      CityA    /3D/Corneria/Scripts/gCityA.txt      # terrain, scenery
RegistStageLayer CityA_1  /3D/Corneria/Scripts/gCityA_1.txt    # enemies, objectives
```

The layer contains only placements:

```
CreateEnemyTemplate eManbo <1850.026 257.2633 -208.3949> <0 0 0> <1 1 1> 1
```

Position and rotation (in degrees) are in world units; the last integer is the
difficulty. The name refers to a **template** defined in
`/Scripts/<Planet>/<Planet>Enemy.txt`, which the game loads according to the
stage's planet:

```
RegistEnemy eHoverEnemy
SetModel HoverEnemy /3D/Enemy/FryEnemy001/FryEnemy001.mdl
SetVolume <50>
SetCallback EnemyHover2
SetLife 20 10 0
SetWeapon 0 10 RegularLaser
```

Everything that follows a `RegistEnemy` up to the next one describes that
template: models (the first `SetModel` is the main one; the `_Demo` aliases
are used for cutscenes), its own texture set, collision volume, behavior
(`SetCallback`), trajectory (`AddPath`), hit points and weapon. Of the 157
names placed in the stages, 141 have a template; the other sixteen are
missiles and bosses defined elsewhere.

### Trajectories

`AddPath <x y z>` stacks up a template's waypoints; `SetPathLoop true` closes
the circuit. The coordinates are **absolute**, in world units: the `eGokai` and
`eShrimp` templates share the same circuit (X −3675..4005, Z −3675..4005)
regardless of their 175 and 133 spawn points, and the altitude of the paths
(600 for `eStarfish`) differs from that of the spawns (650 to 850). An enemy
therefore appears at its `CreateEnemyTemplate` position, then heads for its
first waypoint.

Four `AddPath` and four `SetVolume` calls separate their components with
commas.

## Modifying a script

A script is a `.txt-cmp` file — compressed text — in the data folder or in a
planet's archive. [The procedure](assets.md) explains how to read it, modify
it and put it back, even if it grows; its example, `SetupShared.txt`, was read
back by the game at its new location, with the session following the same path
as with the original.

Each command, with its call count, its signatures and real examples, is in
[`script_reference.md`](../script_reference.md).
